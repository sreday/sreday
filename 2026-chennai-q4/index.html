GuhaTek ❤️ Reliaburger
Your AI agent can already read kubectl output. The trouble is that it was written for human eyes: tables to squint at, exit codes that mean different things in different commands, and log lines that can carry instructions nobody meant it to follow. Hand an agent an admin kubeconfig and you are trusting it to keep promises the cluster never enforces. Reliaburger is a container orchestrator in one Rust binary, written by Miko Pawlikowski after more than ten years of running platform teams on Kubernetes: scheduler, gossip, Raft, eBPF service discovery, ingress, mTLS, registry, metrics, logs, GitOps and chaos testing, driven by TOML. It is also built for agents from the ground up. relish agent answers in one line of JSON that stays within a byte budget, tells the agent which next steps are read-only, wraps everything an app wrote as untrusted, and lets it read the exact source code the cluster runs. An agent never changes the cluster: it proposes, and a person approves. In this hands-on workshop, Balaji puts it in your hands. Bring a laptop running macOS on Apple silicon or Linux with KVM (Windows is not supported yet) and, if you use one, your favourite coding agent: Claude Code, Codex, Cursor, Gemini CLI and others. You will: Install Reliaburger with one command and start a three-node cluster on your laptop. Deploy an app from a twelve-line TOML file. Wire your agent in with relish agent setup (an MCP server, shown as a diff before anything is written) and give it a read-only token that expires. Break things on purpose with the built-in fault injector, then watch your agent find out why with relish agent context and diagnose, following evidence instead of guessing. Let the agent propose the fix, read the blast radius and the undo command, and approve it yourself. Then write a guardrail policy that lets it roll back small apps on its own, and never delete anything. Tell us what broke, what your agent got wrong and what you would want from an agent-ready platform. Reliaburger is free and open source under Apache 2.0, and it is version 0.3.2, so it will break. That is the point, and we want to hear about it. Bring your laptop, your agent and your Kubernetes baggage. Let's see how much of it you need.... Read more

Your runbook has two readers at 3AM now. The tired human it was written for, and the agent standing next to them. The human fills every gap with judgement. The agent fills it with action. Kunal Das

Stop Paying Frontier Prices for Lookup Work

Kimchi.dev
AI workloads have landed on the plates of the same teams that already manage compute, storage and network spend, and the default setup is one frontier model for every task. A file lookup costs the same as an architecture decision. The invoice grows, nothing on it says which task needed the big model, and the platform team inherits the bill. This talk shows the alternative as it runs in an open-source coding agent I use daily. Work is split into roles: a planner decomposes tasks, a builder writes code, a reviewer catches mistakes, and lighter models handle exploration and lookup. Each role goes to the cheapest model that clears its quality bar. Routing decisions are explicit, logged and reversible, and cost is attributed per task, per role and per model from the first day - the same discipline you already apply to every other metered resource. The failure modes get equal time: the task types where cheap models cost more in rework than they save in tokens, what falls back when a tier fails or a model becomes unavailable, and where the big model still wins. You leave with a way to segment your own inference workloads and the wiring to prove or disprove the savings on your own numbers. All of it is open source.... Read more

Abstract

Platform teams spend their time making infrastructure self-service, and then monitor it the same way they monitored the infrastructure underneath. That leaves a gap. Your databases are healthy, your nodes are fine, every dashboard is green, and the platform that provisions all of it stopped working four days ago.

Balaji Venkatesan

GuhaTek ❤️ Reliaburger
WorkshopA Robot Walks Into Your Kitchen: Hands-on with Reliaburger
Abstract

Your AI agent can already read kubectl output. The trouble is that it was written for human eyes: tables to squint at, exit codes that mean different things in different commands, and log lines that can carry instructions nobody meant it to follow. Hand an agent an admin kubeconfig and you are trusting it to keep promises the cluster never enforces.

Reliaburger is a container orchestrator in one Rust binary, written by Miko Pawlikowski after more than ten years of running platform teams on Kubernetes: scheduler, gossip, Raft, eBPF service discovery, ingress, mTLS, registry, metrics, logs, GitOps and chaos testing, driven by TOML. It is also built for agents from the ground up. relish agent answers in one line of JSON that stays within a byte budget, tells the agent which next steps are read-only, wraps everything an app wrote as untrusted, and lets it read the exact source code the cluster runs. An agent never changes the cluster: it proposes, and a person approves.

In this hands-on workshop, Balaji puts it in your hands. Bring a laptop running macOS on Apple silicon or Linux with KVM (Windows is not supported yet) and, if you use one, your favourite coding agent: Claude Code, Codex, Cursor, Gemini CLI and others. You will:

  1. Install Reliaburger with one command and start a three-node cluster on your laptop.
  2. Deploy an app from a twelve-line TOML file.
  3. Wire your agent in with relish agent setup (an MCP server, shown as a diff before anything is written) and give it a read-only token that expires.
  4. Break things on purpose with the built-in fault injector, then watch your agent find out why with relish agent context and diagnose, following evidence instead of guessing.
  5. Let the agent propose the fix, read the blast radius and the undo command, and approve it yourself. Then write a guardrail policy that lets it roll back small apps on its own, and never delete anything.
  6. Tell us what broke, what your agent got wrong and what you would want from an agent-ready platform.

Reliaburger is free and open source under Apache 2.0, and it is version 0.3.2, so it will break. That is the point, and we want to hear about it.

Bring your laptop, your agent and your Kubernetes baggage. Let's see how much of it you need.
